# Архитектура

Документ описывает, как код разделён на слои и где что менять. Он важнее
структуры папок: если правило противоречит привычке, действует правило.

## Слои

```
data/                  контент: тексты и разметка уровня
scripts/core/          чистая логика без сцен: Story, SaveData
scripts/autoload/      глобальные сервисы: GameState, AudioManager, UserSettings
scripts/               игровые узлы: world, player, enemy, interaction, darkness
scripts/ui/            интерфейс: GameUI
scenes/                точка входа и игрок
tests/                 проверки без окна, scenarios — сценарные прогоны
tools/                 генераторы ассетов и заметок релиза
```

Правило зависимостей: `core` не знает про сцены, UI и автолоады; `data`
не знает про код; UI не решает правила игры. Если правило требует
`get_tree()` или узла, оно живёт в узле, а не в `core`.

## Контент в данных

`data/story.json` — все тексты: записки, реплики, концовки. Формат:

```json
"archive_note_1": {
  "title": "ОПИСЬ АРХИВА",
  "lines": ["первая строка", "", "абзац после пустой строки"]
}
```

`Story` склеивает `lines` через `\n` и кеширует результат. Сцена обращается
по ключу: `_show_note_key("archive_note_1")`. Новый текст не требует
правки GDScript.

`data/world_layout.json` — карта: комнаты, стены, двери, мебель, декали,
спавны предметов и интеракции. Координаты заданы массивами
`[x, y]` и `[x, y, width, height]`, текстуры — путями `res://`.
`WorldLayout` превращает их в `Vector2`/`Rect2` и кеширует текстуры.

Новая дверь, предмет или записка на карте — это запись в JSON, а не новый
`const`. Условие появления задаётся `absent_flag`: интеракция не создаётся,
если флаг уже стоит.

## Сохранение

`GameState` хранит рантайм: флаги, инвентарь, цель, чекпоинт, время,
концовку. `SaveData` знает только формат: версию, поля JSON, миграции
и пересчёт координат старых сейвов. Пересборка цели из флагов остаётся
в `GameState`, потому что это правило игры, а не формата.

Формат меняется только через `SaveData.VERSION` и новую ветку миграции.
Старые сейвы должны загружаться: тесты в `tests/test_runner.gd` проверяют
v1 и v2.

## Сессия и мир

`main.gd` — контроллер сессии: меню, старт, пауза, взаимодействия,
концовки, автосейв. `world.gd` строит уровень из `WorldLayout` и владеет
врагом, дверями и светом. `GameUI` только показывает состояние и отдаёт
сигналы; правила в UI не живут.

Сцены сейчас создаются кодом: `world.tscn` — один узел со скриптом.
Это осознанный компромисс альфы. Переход на декларативные `.tscn` —
следующий крупный этап; он не должен менять формат сейва и тексты.

## Экспорт

Godot не включает нересурсные файлы в сборку. Перед первым экспортом
добавьте `data/*.json` и `VERSION` в **Filters to export non-resource
files**. Иконка лежит в `assets/branding/icon.svg` и подключена через
`application/config/icon`.

## Проверка

```bash
tests/run_all.sh                                          # юнит + сценарии
python3 .../check_godot_project.py . --json               # статический чекер
```

Юнит-проверки не поднимают сцену: `SaveData`, `Story` и `WorldLayout`
тестируются напрямую. Сценарные прогоны проверяют сюжет, свет и подвал
на настоящем `main.tscn`.

## Известный долг

- `main.gd` и `game_ui.gd` остаются крупными: взаимодействия и построение
  панелей стоит разнести по контроллерам на глубоком этапе.
- Сцены строятся кодом, а не в редакторе.
- Тесты в основном интеграционные; чистая логика покрыта точечно.
